ESP32 #1 — Motor Controller (Main)

Firmware: esp32_motor_controller.ino

Controls 4× DC motors via 2× TB6612FNG dual H-bridge drivers. Receives throttle:steering commands via UDP :9000 from the laptop. Broadcasts status on UDP :9001. Receives ultrasonic data on UDP :9002. Hosts a web UI on HTTP :8080. Connects in WiFi Station mode (SSID: SANJEEVI). Brownout detection disabled. 500ms command timeout. WiFi auto-reconnect every 5s.

ESP32 #2 — Ultrasonic Sensor (Sensor)

Firmware: esp32_ultrasonic_udp_v1.ino

Reads HC-SR04 ultrasonic sensor every 200ms (5 Hz) and sends distance data via UDP :9002 to ESP32 #1. Also used by the laptop for sensor fusion (ultrasonic takes priority under 30cm). Connects to same WiFi SSID SANJEEVI.

📡 Distance Calculation

Raspberry Pi 5 — Camera Streamer

Script: pi_camera_v2.py

Dedicated camera streaming unit. Captures 640×480 video at ~30 FPS from Pi Camera v2 (CSI) or USB Webcam. Compresses frames as JPEG (quality 75%) and sends over UDP :5000 to the laptop. Frame format: [4-byte size][JPEG data].

Critical Firmware Notes

Hardware safety
Brownout Disabled → WRITE_PERI_REG(RTC_CNTL_BROWN_OUT_REG, 0) ESP32 #1 only
Prevents WiFi dropout when motors spin up and cause voltage dips. Only needed on the motor controller ESP32.
Command Timeout → 500ms — motors STOP if no command received Safety fallback
If the laptop disconnects or crashes, the ESP32 stops the motors within 500ms.
WiFi Auto-Reconnect → Checks every 5s, auto-reconnects if lost Both ESP32s
Sensor Fusion → Ultrasonic < 30cm → YOLO bbox distance > 30cm On laptop
Ultrasonic takes priority under 30cm. YOLOv8 bounding box height estimation used for objects beyond 30cm.
UDP Command Format → throttle:steering (e.g. 150:0.00) Laptop → ESP32 #1
